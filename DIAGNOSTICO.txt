4. PROBLEMAS CONHECIDOS / LIMITAÇÕES
--------------------------------------------------------------------------------

  4.1 AMBIENTE SEM DOCKER/POSTGRESQL (limitação da máquina)
      Build e testes continuam independentes de Docker e PostgreSQL.
      Composição pronta para uso onde houver Docker.

  4.2 TRÊS LIMITAÇÕES BENIGNAS DOCUMENTADAS (não são bugs)
      - Valores negativos: inteiros/decimais aceitam sinal de menos (contrato
        dos helpers de valores monetários).
      - TentarConverter aceita "+5" (função de conveniência, não validador).
      - Remover cliente com aparelho vinculado é bloqueado pelo EF
        (FK) — comportamento documentado, não refatorado sem bug real.

  4.3 PLACEHOLDER DESIGN-TIME (não é segredo)
      DesignTimeDbContextFactory.cs tem connection string localhost
      ("postgres"/"postgres") apenas para gerar migrations sem conexão;
      nunca é usada em runtime (a aplicação exige ConnectionStrings__Default
      por variável de ambiente). Varredura geral não encontrou credenciais
      reais em nenhum arquivo versionado.

  4.4 NENHUM TODO/FIXME/HACK no código do projeto
      (os ocorrências encontradas são de bibliotecas de terceiros em
      wwwroot/lib, não alteradas).

  4.5 ANOTAÇÃO EM OS TERMINAL
      RegistrarAnotacaoAsync não exige status em andamento — uma anotação não
      muda o status, então funciona também em Entregue/Cancelado (situações
      terminais continuam vedadas a MUDANÇA DE STATUS, regra intacta).
