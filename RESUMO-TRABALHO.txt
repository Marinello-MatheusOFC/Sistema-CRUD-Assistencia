4.5 SERVICES (Services/) — regras críticas de negócio
  ClienteService
    - ListarAsync com busca por CPF, nome, telefone ou e-mail
    - BuscarPorCpfAsync já normalizado
    - Bloqueia CPF duplicado (checagem na aplicação + captura da corrida
      entre duas telas via índice único do banco)
    - Desativar/Reativar em vez de excluir (preserva histórico)

  AparelhoService
    - ListarPorClienteAsync, BuscarPorImeiAsync
    - Grava IMEI como NULL quando vazio (não é obrigatório)
    - Impede aparelho órfão

  OrdemServicoService
    - AbrirAsync: valida cliente ativo, valida que o aparelho é do cliente,
      normaliza campos, status inicial Recebido, calcula total, gera
      NumeroOS em 2 etapas (INSERT para obter Id, depois UPDATE) e registra
      o primeiro item do histórico
    - AlterarStatusAsync: grava histórico com status anterior, novo status,
      observação e usuário
    - FinalizarAsync: grava DataConclusao e move para Pronto
    - RegistrarRetiradaAsync: grava DataRetirada e move para Entregue
    - AtualizarAsync: recalcula o total, nunca confia no formulário
    - Regras: Entregue e Cancelado são status TERMINAIS (não voltam atrás);
      retirada só é permitida quando o status é Pronto

  BuscaService ....... busca unificada (reutiliza os outros 2 services)
  DashboardService ... contagens por status + últimas 10 OS
  Endereco/ViaCepService .. consulta à API gratuita do ViaCEP; devolve null
                          em falha de rede e o cadastro continua funcionando
  RegraDeNegocioException .. erro de regra vira mensagem de formulário
  SeedExecutor ........ cria o usuário admin e os dados de exemplo
